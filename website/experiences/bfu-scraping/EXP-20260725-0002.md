## 1. Objective
Scrape final score, both sides' starting XI + reserves (number + name), goal scorers, cards (yellow/second-yellow/red), and substitutions with minutes from a bfu-tournaments.com match page, using Jsoup against the raw HTTP response (no live network calls in tests).

## 2. The Trap
Two false leads waste time here: (1) live-DOM textContent via javascript_tool comes back EMPTY for most visible strings (e.g. status banner) because some labels are client-rendered -- this can wrongly suggest the whole page needs JS execution/anti-scraping workarounds, when in fact the specific data you need (names, numbers, score, event tooltips) IS present as literal text in the plain curl/Jsoup response; verify with curl+grep on the raw response before assuming JS rendering is required. (2) SVG icon filenames are Vite-hashed per build (e.g. yellow-card-CamUuf9s.svg) -- match on a src.contains(meaningfulPrefix) substring, never the full hashed filename, and note 'second-yellow-card' contains the substring 'yellow-card' so check the more specific icon name first in an if/else chain.

## 3. Abstracted Insight
> **Core Principle:** For a Livewire/Alpine/Tailwind-built page, don't trust in-browser textContent/DOM reads alone to decide whether server-rendered data exists -- some static UI chrome labels really are client-injected, but domain data usually isn't. Confirm what the raw HTTP response actually contains (curl with a realistic User-Agent, grep for expected literal strings) before concluding a scraper target needs headless rendering. Once confirmed static, distinguish sibling event types (home vs away, card vs goal vs substitution) via structural/attribute signals that survive a rebuild (a stable class like flex-col-reverse, an element count inside a tooltip anchor) rather than exact hashed asset names or brittle text positions.

## 4. Validated Path
1) curl the target page with a browser-like User-Agent and referrer, save to a scratch file. 2) grep for literal expected strings (team names, a known player name) to confirm the data is server-rendered before assuming JS execution is needed. 3) Use the live browser (get_page_text, screenshot, zoom) only to learn the VISUAL structure/icon meanings (which icon = which event type, top row = home vs bottom = away), then re-derive the actual selectors from the raw curl'd HTML, not from live DOM reads. 4) For icon-based event typing, grep across a range of nearby match IDs (curl in a loop/xargs -P) to discover all icon variants that occur in practice (goal, yellow-card, second-yellow-card, red-card, substitute) before hardcoding a fixed icon vocabulary -- a single sample match will not show rare events like red cards. 5) Match icon src via String.contains on the meaningful prefix, checking more specific names (second-yellow-card) before their substrings (yellow-card). 6) Save the real curl'd page(s) as test fixtures (matching the existing bfu-league-page.html convention) rather than hand-writing synthetic HTML, since exact class names/structure matter and are easy to get subtly wrong by hand.
