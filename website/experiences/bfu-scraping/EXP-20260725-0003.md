## 1. Objective
Given a competition (league) and a target date, find which match(es) were played that day and get each one's /stats/match/{id} detail-page URL, without needing a dedicated per-date API.

## 2. The Trap
Two false leads: (1) assuming round-accordion clicks fetch data via AJAX/Livewire and trying to reverse-engineer that endpoint -- read_network_requests shows nothing fires, it's pure Alpine.js visibility toggling over data already in the DOM. (2) The date cell has no year (BFU site shows only day+month+weekday), so don't try to infer a year from the season string's boundary -- since the whole page is already scoped to one season, comparing only day+month (java.time.MonthDay) against the target LocalDate's day+month is sufficient and avoids season-year-boundary guessing entirely.

## 3. Abstracted Insight
> **Core Principle:** For a Livewire/Alpine accordion-style page, confirm with read_network_requests whether expanding a section triggers a request before assuming server-side pagination/filtering is needed -- if nothing fires, the full dataset is already static in the initial HTML and a plain Jsoup GET captures everything, no headless rendering or endpoint reverse-engineering required. Separately, when a listing's date field omits the year, compare on the year-agnostic parts you actually have (day+month) rather than reconstructing a full date -- MonthDay is the right JDK type for this rather than picking an arbitrary placeholder year (which risks a Feb-29-on-non-leap-year crash if picked carelessly).

## 4. Validated Path
1) Navigate to the league page and find its view-switcher tabs (Класиране/Програма/Резултати/Голмайстори); click 'Резултати' and note the URL gains &view=past-matches -- a plain query param, directly Jsoup-fetchable. 2) Call read_network_requests after clicking a round's accordion header to confirm no request fires (proves it's client-side-only, full data already present). 3) curl the &view=past-matches URL directly and grep for 'Кръг N' markers to confirm all rounds (not just the default-open one) are present in the raw response. 4) Identify the per-match <tr> structure (4 <td>s: date, home dd, result <a href=stats/match/{id}>, away dd) via narrow grep/sed slices of the curl'd file, not outerHTML browser reads. 5) Save a real curl'd copy as the test fixture, trimmed to 2-3 rounds (via clean line-range boundaries between round <div> wrappers) to keep the fixture size reasonable while staying 100% real captured markup, not hand-authored.

## 5. Verification Checklist
