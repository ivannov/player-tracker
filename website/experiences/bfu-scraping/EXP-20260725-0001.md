## 1. Objective
Learn a real page's DOM structure (tag names, classes, attribute names, form field names) accurately enough to write correct Jsoup CSS selectors and a realistic test fixture, before writing any scraper code against a site with no prior fixture.

## 2. The Trap
Reaching for document.documentElement.outerHTML / element.outerHTML / element.innerHTML (or a custom JS serializer that concatenates tag+attributes+children into one string) via the javascript_tool to dump a page's markup for use as a fixture. This is silently refused with '[BLOCKED: Cookie/query string data]' as soon as the returned string contains multiple space-separated key="value" attribute pairs -- which is true of almost any real-world HTML element with more than one attribute. Retrying with base64 or other encodings to slip the payload through is also blocked and should not be attempted -- it's working against a deliberate safety boundary, not a bug.

## 3. Abstracted Insight
> **Core Principle:** The filter operates on individual property reads, not on the whole page or the code text. tagName, className, a single attribute's value via getAttribute(name), and textContent/innerText all return cleanly. Only the *serialized multi-attribute HTML string* trips it. So: walk the DOM and pull one safe primitive at a time (tag name, one attribute at a time, cell text, row/cell counts via .rows/.cells, child counts) and reconstruct the structure as notes/JSON in your own head or scratch file, then hand-write a fixture HTML file from that reconstruction. This is slower than dumping outerHTML but is real, verified structure -- not guesswork -- and stays inside the tool's intended boundary. A get_page_text call (plain text extraction) is unaffected and is a good first pass to see what content exists before drilling into structure.

## 4. Validated Path
1) Navigate to the target page with claude-in-chrome. 2) get_page_text for a quick content overview. 3) Use javascript_tool with narrow, single-purpose reads: document.querySelectorAll(sel).length, element.tagName, element.className, element.getAttribute('name'|'value'|'width'|...) one at a time, element.textContent, and table.rows/table.cells for tabular layouts -- never element.outerHTML/innerHTML or a custom serializer. 4) For forms, enumerate input names/types individually (input.type, input.name, input.value) to learn the real POST field names instead of guessing. 5) Build a hand-written fixture HTML file mirroring the confirmed tag/class/attribute names, with representative (not necessarily complete) sample rows. 6) If the site turns out to require login, first check whether the specific sub-path you actually need is public before concluding the whole scraper needs an auth flow -- ask the user for the exact path if unsure, they may know a public sub-app (as with ebfu.net/teams/).

## 5. Verification Checklist
- [ ] Before assuming a whole domain needs login, check whether the specific path the task needs is actually public.
