## 1. Objective
Write a test that asserts on the body of the page a 303 redirect points to, when that redirect's query string was built with URLEncoder.encode server-side.

## 2. The Trap
given().when().get(location) with location a raw absolute URL string containing already-percent-encoded query chars (e.g. ?error=%D0%93...) makes RestAssured re-encode the % signs (default urlEncodingEnabled=true), so the server decodes only one layer and @QueryParam binds the literal percent-encoded text instead of the real message -- the test fails even though production/browser behavior is correct.

## 3. Abstracted Insight
> **Core Principle:** RestAssured assumes any query content embedded in a plain URL string is raw/unencoded and will encode it before sending, unless told otherwise. This only bites when you manually construct a request to an already-encoded URL (e.g. following up on a captured Location header); it never affects RestAssured's own .queryParam(name, value) helper, which encodes exactly once.

## 4. Validated Path
Add .urlEncodingEnabled(false) to the given() call before hitting a pre-encoded absolute URL captured from a response header: given().urlEncodingEnabled(false).when().get(location).

## 5. Verification Checklist
- [ ] When a test does given().get(someCapturedUrl) where someCapturedUrl came from a Location header or similar and contains a query string, add urlEncodingEnabled(false) to avoid double-encoding
