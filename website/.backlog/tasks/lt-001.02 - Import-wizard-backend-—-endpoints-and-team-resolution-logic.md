## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Implement the REST layer for the participation import wizard (LT-001). The wizard is driven entirely by HTMX — each step is a server-rendered Qute partial.

**Endpoints (new resource `ParticipationImportResource` at `/participations/import`):**
- `GET /participations/import` — render step 1: URL input + competition selector + season field
- `POST /participations/import/extract` — HTMX: call the BFU scraper (LT-001.01), match each name case-insensitively against `Team.name`, return step 2 partial with resolution rows
- `POST /participations/import/formations` — HTMX fragment: given a `teamId`, return a `<select>` of that team's existing `TeamFormation` rows
- `POST /participations/import/save` — create all Participations; auto-create missing Teams and TeamFormations from form data; redirect 303 to `/participations`

**Team-resolution model (carried through the form):**
Each row in step 2 carries: `scrapedName` (display only), `teamId` (resolved or blank), `teamName` + `teamLocation` (only when creating new), `formationTypeId` (selected formation id or blank), `newFormationType` (FormationType enum, only when creating a new formation).

**Business rules:**
- Season from URL query param (`2024-2025`) must be normalised to DB format (`2024/2025`) before saving
- Unique constraint on (team_formation_id, competition_id, season) — skip silently if Participation already exists
- Wrap entire save in a single transaction
- Security: `@Authenticated` on GET, `@RolesAllowed("ADMIN")` on POST methods

Context:
- Package root: `com.nosoftskills.lineup`; resources under `.../resource/`
- Use `@RestForm` (resteasy-reactive), not `@FormParam`
- All entities extend `TrackerEntity`; `@JoinColumn` required for camelCase FK fields
- BFU scraper service provided by LT-001.01

### Modified files
- `pom.xml` — add quarkus-junit5-mockito test dependency
- `src/main/resources/templates/ParticipationResource/list.html` — add "Импорт от БФС" button

### Package
`com.nosoftskills.lineup.participation` (follows domain-subpackage convention)

### HTMX flow
- GET returns full page with step1 form inside `<div id="import-wizard">`
- POST /extract returns step2 fragment with same outer id → outerHTML swap replaces wizard
- Team select in unmatched rows triggers POST /formations → innerHTML swap of formations span
- POST /save is a plain form submit → redirects 303

### Multi-value form fields (one per row, in order)
scrapedName, teamId, teamName, teamLocation, formationTypeId, newFormationType — all always present (blank hidden inputs for N/A fields)

### Season normalisation
`season.replace("-", "/")` in /save

### Error handling
BfuScraperException → throw BadRequestException (400); no error-UI template needed (not in ACs)
