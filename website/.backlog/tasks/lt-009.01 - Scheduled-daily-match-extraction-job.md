## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Added CompetitionExtractionConfig (new competition_extraction_configs table, 1:1 with Competition via competition_id UNIQUE FK) instead of columns on Competition itself, keeping the scheduling-specific fixturesUrl/currentSeason out of the core entity. CompetitionResource's existing edit form gained two fields wired to this config (upserted on save; blanking either field deletes the config row, disabling scheduling for that competition). New ScheduledExtractionJob (@Scheduled cron 0 0 23 * * ?, concurrentExecution=SKIP) queries configs whose competition has >=1 Participation (short QuarkusTransaction.requiringNew() query, kept separate from the blocking scraper I/O) and calls MatchExtractionService.confirm(...) per competition for LocalDate.now(), catching BfuScraperException per-competition so one failure doesn't block the rest. Added ScheduledExtractionJobTest (config+participation combinations, failure isolation) and extended CompetitionResourceTest for the new config upsert/delete behavior. mvn verify green.
<!-- SECTION:NOTES:END -->
