## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
PlayerMatchingService (com.nosoftskills.lineup.matching): exact player_aliases hit short-circuits; else a native pg_trgm similarity() query scoped to players with a PlayerAppearance for a participation of the given team_id (not the whole players table); single top candidate with similarity >= 0.6 AND at least 0.05 clear of the runner-up auto-resolves + writes a player_aliases row; otherwise queues an ambiguity_reviews row with ranked ambiguity_candidates (including the zero-candidate case). Thresholds are hardcoded constants on the service (no existing @ConfigProperty pattern in this codebase to follow). ParticipationImportResource.save() now writes/updates a TeamExternalRef (source=BFU_TOURNAMENTS, external_key=the raw scraped name) for every resolved-or-created team, find-or-update so repeat imports don't hit the (source, external_key) unique constraint. Debugged a Hibernate 7 quirk: loading a TeamExternalRef entity and touching its lazy .team association, then bulk-deleting other rows in the same transaction, threw TransientPropertyValueException at commit; switched that test assertion to a count() projection instead of touching the lazy association, which avoided it entirely -- worth remembering if this pattern (load entity with lazy to-one, then bulk-delete in same tx) recurs elsewhere. mvn verify: 129/129 tests pass.
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Added PlayerMatchingService (com.nosoftskills.lineup.matching), a new domain subpackage following the scraping/ and participation/ pattern: resolves a raw scraped player name scoped to a team via an exact player_aliases lookup, falling back to a pg_trgm similarity() query restricted to players who have appeared for that team (via PlayerAppearance/Participation/TeamFormation), auto-resolving a single confident match with an alias write-back or queuing an ambiguity_reviews row with ranked ambiguity_candidates otherwise -- never guessing. Also closed the LT-001.02 gap: ParticipationImportResource.save() now records a TeamExternalRef (source=BFU_TOURNAMENTS, external_key=the raw scraped name) for every resolved-or-created team, idempotently, so re-encountering the same team next season is an exact lookup. Verified with new PlayerMatchingServiceTest (exact-alias short-circuit, confident auto-resolve + write-back, tied-candidate and low-score ambiguity queuing) and new ParticipationImportResourceTest cases for TeamExternalRef creation/reuse, plus a full mvn verify (129/129 tests pass).
