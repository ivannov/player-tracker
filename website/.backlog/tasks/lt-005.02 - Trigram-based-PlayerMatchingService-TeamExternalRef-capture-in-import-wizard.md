## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 PlayerMatchingService resolves a raw scraped name scoped to a team_id: an exact player_aliases hit short-circuits immediately with no ambiguity
- [ ] #2 Absent an alias hit, it runs a trigram similarity() query scoped to players who have ever appeared (via PlayerAppearance/Match/Participation) for that team_id -- not the whole players table
- [ ] #3 A single confident match above a defined similarity threshold auto-resolves and writes a new player_aliases row
- [ ] #4 Below-threshold or multiple close candidates create an ambiguity_reviews row with ranked ambiguity_candidates instead of guessing
- [ ] #5 ParticipationImportResource's save step (participation/ParticipationImportResource.java) persists a TeamExternalRef for each resolved-or-created team
- [ ] #6 Unit tests cover: exact-alias short-circuit, confident auto-resolve with alias write-back, and ambiguous-case queuing
<!-- AC:END -->
