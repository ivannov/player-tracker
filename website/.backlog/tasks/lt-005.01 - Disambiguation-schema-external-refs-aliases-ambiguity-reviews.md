## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
New migration src/main/resources/db/migration/V3__disambiguation.sql plus new entities model/TeamExternalRef.java, model/PlayerAlias.java, model/AmbiguityReview.java, model/AmbiguityCandidate.java.

team_external_refs scopes a team's raw scraped name by source so re-encountering the same team next season is an exact lookup, not a fresh fuzzy match.

player_aliases is scoped by team_id (the team the name was scraped under), not globally -- a player transferring to a new team is correctly treated as a fresh resolution rather than an auto-match, which matters because two different players can share a common Bulgarian name.

ambiguity_reviews/ambiguity_candidates model the admin inbox item: a raw name that couldn't be confidently resolved, with its ranked candidate players and a resolution outcome once an admin acts on it. This is pure schema/entities -- no service logic or UI in this task, that's LT-005.02 and the daily-scheduler epic respectively.
