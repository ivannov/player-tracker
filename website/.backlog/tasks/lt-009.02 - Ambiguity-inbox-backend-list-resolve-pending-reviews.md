## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
New service/resource to power the admin ambiguity inbox: list PENDING AmbiguityReview rows with their ranked AmbiguityCandidate players (ordered by score desc), and a resolve action. Refactor PlayerMatchingService.writeAlias(...) from private to a reusable public entry point, then add a public resolveReview(Long reviewId, Long chosenPlayerId) (picks an existing candidate/player) and a 'confirm as new player' variant (creates a new Player, then aliases it) -- both write into player_aliases exactly like the wizard's confirm path, and both update the AmbiguityReview row (status=RESOLVED, resolvedPlayer, resolvedAt, resolvedBy from CurrentUser). New InboxResource (@RolesAllowed("ADMIN") for all endpoints -- this is an admin-only screen per the epic description, unlike the public-read/admin-write pattern used elsewhere) exposing list + resolve endpoints for the LT-009.03 UI to call.
<!-- SECTION:DESCRIPTION:END -->
