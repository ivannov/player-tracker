## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Live recon of ebfu.net/teams/ (2026-07-25): single form, POST curDate=<yyyy-MM-dd>&selectDateBtn=1 for the day list, POST curDate+showMatchBtn=<internal id> for a match's lineup page. Day-list card: table.teamTable > tr > td[1]=logo, td[2]=(div.teamName home, div.teamCity), td[3]=(div.teamCity comp, div.teamName time), td[4]=(div.teamName away, div.teamCity), td[5]=logo, plus sibling input[name=showMatchBtn][value=matchId] in the same td (whole form resubmits, so curDate rides along automatically). Lineup page: two td[width=450] columns, each = starters table (header td.robotoWhiteB20=team name, rows of td=number/td=name+optional ' - ВРАТАР'/' - КАПИТАН' suffix) + reserves table (same shape, header 'Резерви') + trailing span.robotoBlack20 'Главен Треньор:' + span.robotoBlackB20=coach name.
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Added EbfuMatchLineupScraperService (com.nosoftskills.lineup.scraping): a two-step Jsoup POST flow against the public https://ebfu.net/teams/ endpoint (verified live -- no login required, unlike the ebfu.net root portal). Step 1 POSTs curDate+selectDateBtn=1 to get the day's match-card list, findMatchId() scans it for a card whose two team-name divs match the requested home/away names (case-insensitive containment) and returns its showMatchBtn value, throwing EbfuScraperException on zero or multiple matches. Step 2 POSTs curDate+showMatchBtn=<id> to get the match page; parseLineup() reads the two td[width=450] side columns, each holding a starters table and a Резерви (reserves) table, into EbfuTeamLineup/EbfuLineupEntry records, splitting the ВРАТАР (goalkeeper) / КАПИТАН (captain) suffixes off each scraped name. Mirrors BfuLeagueScraperService's public-extract/package-private-parse split so parsing is fixture-tested without live network. Fixtures (ebfu-day-list.html, ebfu-match-lineup.html) were hand-built from real page structure captured via live browser recon, since the browser tool blocks raw HTML/outerHTML extraction as an anti-exfiltration safety measure. mvn verify: 143/143 tests pass. Created LT-006.02 (model-mapping into the future wizard's shared contract) as a separate pending subtask, left unimplemented since LT-007/LT-008 haven't established that contract yet.
